# LIX Buddy 데모 사이트 설계

작성일 2026-09-02 · 상태: 사용자 승인 · 근거: 레인보우피크닉 STEP2 AI 비즈니스 모델 사업계획서(2026-09-01, 이 레포에 사본을 두지 않음) · 브레인스토밍 세션 결정(§1) · 선행 사례: `qtrace-demo`(금산패드 데모)

## 1. 목적과 결정 사항

**목적.** 레인보우피크닉(기술브랜드 LIXLABS)이 2026년 혁신 소상공인 AI 활용지원 STEP2 발표평가에서 띄우거나 발표자료 캡처에 쓰는 **소개용 데모 사이트**. MVP도, 기능 검증도 아니다. "학생이 만든 태그를 교사가 안전운영에 쓴다"는 한 이야기를 7개 장면으로 전달한다.

**브레인스토밍에서 확정한 것.**

| 항목 | 결정 |
|---|---|
| 형태 | 소개 페이지 1장 + 시나리오 데모(장면을 [다음]으로 넘기고, 장면 안에서 클릭도 됨) |
| 서사 | 단일 서사 7장면. 학생 제작 4장면 + 교사 안전운영 3장면. 같은 태그 `LB-0917-03`이 관통 |
| 스타일 | 학생 장면은 태블릿 수업 앱 톤(둥근 모서리·밝은 색·큰 그림카드), 교사 장면은 King Check 업무 화면 톤(금산패드 데모와 같은 밝은 업무 화면 + 남색 포인트). 한 데모 안에서 `mode`로 껍데기를 바꾼다 |
| 표기 | 레인보우피크닉·LIXLABS·LIX Buddy·King Check·Tripo는 실명. 학교·학급·학생·수치는 전부 가상. 사람은 역할명(담당교사·제작담당·보호자)과 학생 별칭만. 사업자번호·사업비·대표자 개인정보는 어디에도 없음 |
| 개발사 표기 | 푸터 한 줄 "시연용 가상 데이터 · 세종AI연구센터" |
| 안전 문구 | 계획서의 경계를 화면에 그대로 반영: "보조도구", "의심 이벤트", "교사 확인", "구역 기반이며 좌표 추적 아님", "실제 Tripo 출력 아님", "시연값" |
| 구현 | 무빌드 정적 파일. 외부 자원(CDN·웹폰트·스크립트) 없음. `file://`로 열어도 동작(ES 모듈·fetch 미사용, 데이터 인라인) |
| 위치·배포 | 이 레포 `rainbow` 한 곳에 설계서·플랜·데모 코드. 계획서 docx 사본은 넣지 않는다(OneDrive 원본 참조). 공개 가능한 내용만 두어 GitHub Pages(master 루트) 배포가 가능하게 한다 |
| 재사용 | `qtrace-demo`의 장면 엔진(`js/demo.js`), 테스트 하네스(`test/`), CSS 토큰 구조를 가져와 수정 |
| 캐릭터 자산(2026-09-02 추가 결정) | 장면 2의 AI 그림과 장면 3의 3D는 사용자가 준비한 실제 자산(AI 이미지 3장, Tripo GLB 1개)을 `assets/`에서 읽는다. 자산이 없으면 절차적 3D·SVG로 자동 대체되어 데모가 깨지지 않는다. 3D는 Three.js 오프라인 번들 |

**공개 범위 근거.** 계획서 원문에는 사업자번호·사업비 가안·대표자 경력이 있다. 이 레포에는 HTML·CSS·JS와 가상 데이터, 그리고 계획서의 공개 가능한 표현(사업 정의·문제 진단·AI 역할 경계·성과 목표)만 둔다.

## 3. 시나리오 데모 (`demo.html`)

### 3.1 화면 껍데기 두 가지

장면마다 `mode` 값이 있고, 엔진이 `<body class="mode-student">` 또는 `mode-teacher`로 바꾼다. 두 껍데기는 `demo.html`에 모두 존재하며 CSS로 한쪽만 보인다.

**학생 모드(장면 1~4, `studio.css`)**
- 상단 바: 로고 "LIX Buddy 만들기", 학생 별칭 "파랑이", 4단계 진행 표시(약속 → 캐릭터 → 3D → 출력, 현재 단계 강조), 오른쪽 끝 [그만하기] 버튼(항상 보임).
- 사이드바 없음. 본문 최대 폭 1100px 가운데 정렬. 카드 모서리 16px, 버튼 높이 56px 이상, 본문 18px 이상.
- [그만하기] 클릭: 본문 위에 안내 카드 "괜찮아요. 오늘은 기본 쉘로 함께해요. 언제든 다시 만들 수 있어요" + [돌아가기]. 장면 상태는 바뀌지 않는다.

**교사 모드(장면 5~7, `app.css`)**
- 상단 바: 로고 "King Check", 경로 표시(예: 세션 › 과학관 체험학습), 학교 배지 "햇살특수학교(가상)", 알림 아이콘(장면 6 이후 배지 2), 사용자 "담당교사".
- 사이드바(아이콘 + 라벨): 대시보드, 세션, 학생·태그, 알림, 보고, 만들기 수업. 현재 장면 항목 활성. 클릭하면 아래 장면으로 이동.

  | 메뉴 | 장면 |
  |---|---|
  | 대시보드 | 7 |
  | 세션 | 5 |
  | 학생·태그 | 5 |
  | 알림 | 6 |
  | 보고 | 7 |
  | 만들기 수업 | 2 |

**공통**
- 본문: 장면의 `render()`가 채운다.
- 상단 고지(두 모드 공통, 얇은 띠): "시연용 가상 데이터 · 실제 학생·학교·AI 출력이 아닙니다".
- 하단 데모 바: "장면 3 / 7 · 2D에서 3D로", 한 줄 설명, [이전] [다음], 장면 점(7개, 클릭 가능). 캡처 모드에서 숨김.
- 발표 메모: 하단 바 위에 접히는 패널. 기본 꺼짐.

### 3.2 키보드와 URL

| 입력 | 동작 |
|---|---|
| `→` / `←` | 다음 / 이전 장면 |
| `1`~`7` | 해당 장면으로 |
| `N` | 발표 메모 토글 |
| `C` | 캡처 모드 토글(상단 바·사이드바 유지, 하단 데모 바·메모·장면 점·상단 고지 숨김) |
| `R` | 현재 장면 초기화 |
| `demo.html#4` | 장면 4로 바로 열기. 장면 전환 시 해시 갱신 |

장면에 들어갈 때마다 `reset()`이 호출되어 상태가 처음으로 돌아간다. 장면 2에서 입력 중인 텍스트 필드에 포커스가 있을 때는 숫자·문자 키 단축키를 무시한다.

### 3.4 장면 규약

```js
// js/scenes/s3-model.js
registerScene({
  id: 3,
  mode: "student",          // "student" | "teacher"
  key: null,                // 교사 모드에서만 사이드바 메뉴 키. 학생 모드는 null
  title: "2D에서 3D로",
  summary: "Tripo가 외형을 만들고 규칙 엔진이 BLE 코어 공간을 넣는다",
  note: "발표 메모 문장",
  render(root, data) { /* root.innerHTML = ...; 이벤트 바인딩 */ },
  reset() { /* 내부 상태·타이머 초기화 */ },
});
```

엔진(`demo.js`)은 `registerScene`으로 모인 배열만 다룬다. 장면은 `data`(§4)만 읽고 서로를 참조하지 않는다. 지연 실행은 장면 3·4·5·6이 `LB.later(fn, ms)`로만 걸고, 엔진이 장면 전환 시 대기 타이머를 전부 해제한다(`LB.clearTimers`). 테스트는 `LB.sync = true`로 즉시 실행한다.

**qtrace-demo 엔진 대비 변경점**: ① 장면 규약에 `mode` 추가, `paintChrome`이 `body` 클래스를 바꿈 ② `MENU`를 교사 모드용으로 교체하고 학생 모드에서는 사이드바를 그리지 않음 ③ 학생 모드 상단 진행 표시(1~4단계)를 `paintChrome`이 갱신 ④ [그만하기] 안내 카드 토글을 엔진이 담당 ⑤ 포커스가 입력 필드에 있으면 단축키 무시 ⑥ `LB.later`/`clearTimers`/`sync` 타이머 관리. 그 외 등록·전환·해시·키보드·캡처·메모·reset 로직은 그대로.

## 7. 하지 않는 것

실제 AI 이미지·Tripo 호출, 실제 BLE·게이트웨이 통신, GPS 지도·좌표 표시, 충격·낙상 판정 화면, 보호자용 앱·동의 화면, 로그인, 저장, 다국어, 모바일 최적화, 검색, 인쇄 최적화. 장면 표(§3.3)에 없는 버튼은 동작하지 않는다. 계획서의 실측 빈칸(BLE 모듈 실측치, 매출, 인건비)을 흉내 내는 수치는 넣지 않으며, 화면의 시간·건수·치수에는 "시연값"을 붙인다. 소개 페이지에 사업비·가격·매출 시나리오는 넣지 않는다.
